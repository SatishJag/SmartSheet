# "All" — full project plan Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** An **All (full project plan)** option in Plan with AI: a built-in 199-activity Data centre master schedule (template + real history, 7-day calendar, backward from RFS, package rows tagged with cost codes), and the existing Properties master listed first under the same label.

**Architecture:** A one-off script turns the owner's workbook into a committed catalog module (`dcMaster.ts`) and seed migration (`0023_dc_master.sql`), as for Properties. A pure builder makes the draft from the catalog plus per-package long-lead history (real history only, converted to calendar days); the server uses it for `dc-master` with no AI. The wizard gets a no-items mode for `dc-master` and the "All" label; the sheet builder tags package rows with their cost codes.

**Tech Stack:** TypeScript, React 18, Node server, Supabase/Postgres (PGlite tests), Vitest, Playwright, Python 3 + openpyxl (generator script only).

**Spec:** `docs/superpowers/specs/2026-11-22-full-plan-design.md`

## Global Constraints
- Schedule type id `dc-master`, name "Data centre master schedule", `project_types {data-centre}`, position 0, target `DC-0192`.
- Full-plan schedule types (shown as **All (full project plan)**, first in the list): `dc-master`, `property-development`.
- Package table: Chillers → Chiller / CHL; Generator Sets → Diesel generator / GEN; Transformers → Power transformer / TRF; Switchgear → HV switchgear / HVS; Power Modules → none / none; Fan Wall Units (FWU) → none / none.
- Step history codes (steps 1–7; 8 template; 9 milestone): 1 SPEC · 2 RFQ+BIDEVAL · 3 AWARD · 4 DWGSUB+DWGAPP · 5 MFG · 6 FAT · 7 RELEASE+SHIP+CUSTOMS+DELIVER.
- Calendar days from working days: `Math.ceil(workingDays * 7 / 5)` on the summed p50s. History counts only when `!sampleOnly && projectCount > 0` and every code of the step has stats.
- FAT link lag (SS from manufacture) = `max(0, manufactureDays - 30)` when manufacture comes from history; otherwise the template's 172.
- 7-day calendar = the template calendar with `workingWeekdays: [0, 1, 2, 3, 4, 5, 6]`.
- Basis texts: template → `template`; history → `p50 of <n> projects (<equipment type>), in calendar days`; milestones → as today (`default`, "Milestone: takes no time.").
- Data centre sheet name: `Full plan – <project name>`. Properties keeps today's naming and flow.
- The owner's workbook is not committed; only generated output is. Don't run Prettier.

## Review Focus
- **Sample-only history must leave durations untouched**: with today's data every package equals the template (spec decision). → Task 2 `keeps the template when the history is sample only`.
- **A step whose history covers some codes but not all** (e.g. no DELIVER stats): keep the template for that step, not a partial sum. → Task 2 `keeps the template when a step's code has no statistics`.
- **Project with no name** (or not chosen): Data centre All must refuse Generate like today ("Choose the project"), never send an empty equipmentName. → Task 5 `requires the project for Data centre All`.
- **Cost code list without one of the package codes** (e.g. HVS not in planner): that package's rows get no cost code, nothing crashes. → Task 4 `leaves a package uncoded when its code is not offered`.
- **The 7-day calendar reaching the sheet**: the created sheet's calendar must be the 7-day one, not just the preview's. → Task 5 `creates the sheet on the 7-day calendar`.
