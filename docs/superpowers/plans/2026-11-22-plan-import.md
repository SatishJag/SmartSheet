# Import a plan from Excel: Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** In Plan with AI, upload an `.xlsx`/`.csv` project plan. The reader copies its activities exactly, the server fills blank durations (template/history, or an AI estimate) and detects the schedule type. The planner confirms the project, type and handover date on a "What we found" step, previews the plan, and creates one sheet.

**Architecture:**
- **Browser:** reads the workbook (`read-excel-file`, loaded lazily), finds the activity table by its headings, parses rows, predecessors, status and the Basis of Plan.
- **`POST /api/planner/import`:** maps unknown layouts with the AI, or, for the copied activities, matches the schedule type against the catalogs, takes template durations and links from history/catalog, and asks the AI only for durations of added activities.
- **Browser again:** assembles a `PlanDraft`, then uses the existing backward planner, preview and sheet builder.

**Tech Stack:** TypeScript, React 18, Node `http` server, Anthropic SDK tools, Vitest + Testing Library, Playwright, `read-excel-file`.

**Spec:** `docs/superpowers/specs/2026-11-22-plan-import-design.md`. Read it whole, including "Answers after the builder check".

## Global Constraints

- **Limits:** files up to 10 MB and up to 500 activities. Messages: `"<file>" is larger than 10 MB` and `This file has <n> activities; the import takes up to 500.`
- **Exact copy:** activity code, name, stage, milestone flag, responsibility, criteria and file predecessors are never changed by the server or the AI.
- **What the server and AI receive:** no row data other than headings plus up to 30 sample rows (column mapping only), and `{ code, name, phase, hasDuration, hasPredecessors }` per activity. Nothing is stored. Logs hold counts only.
- **Basis text, exactly:**

  | Duration source | Basis text |
  |---|---|
  | The file | `from your file` |
  | The file's start and finish dates | `from your file's dates` |
  | Template with no history | `from the template, no history yet` |
  | History | `p50 of N projects`, `p80 …` (as today) |
  | AI | `AI estimate: <reason>` |
  | AI failure | `default: no AI estimate available` (5 days) |
  | Template links used | `; links from the template` appended |
- **Status:**
  - `To plan` / `Not started` / blank → `Not started`
  - `In progress` / `Started` / `Ongoing` → `In progress`
  - `Complete` / `Completed` / `Done` → `Complete`
  - `On hold` → `On hold`
  - anything else → `Not started`, with a warning
- **Hourly limit:** a call to `/api/planner/import` costs 1 hourly unit only when it calls the AI, else 0. Every call takes an in-flight slot.
- **Request size:** up to 1 MB on `/api/planner/import`. The other routes keep 16 KB.
- **Preview for imports:** the Regenerate controls are hidden, and Back goes to "What we found".

## Review Focus

1. **Duplicate or self-referencing IDs, links to codes that don't exist, and cycles:** clear warnings or errors, never a crash. Pinned in Task 2 (parse) and Task 4 (cycle → error on "What we found").
2. **Correcting the schedule type** re-fetches durations and links, so nothing stays from the wrong template. Pinned in Task 5.
3. **A file with neither predecessors nor matched template activities:** a plan with a warning, not a crash. Pinned in Task 4.
4. **Dates as Excel serials or `dd/mm/yyyy` text:** the reader normalises them to ISO, and anything unparseable is ignored with a warning. Pinned in Task 1 / Task 2.
5. **The AI returns garbage** (missing codes, negative days, unknown fields): it's validated, and the 5-day default is used. Pinned in Task 3.

### Task 2: Find the table and parse rows

**Interfaces:**
- Consumes: `Workbook` and `toIsoDate`.

  - `interface TableMapping { sheet: string; headingRow: number; fields: Partial<Record<ImportField, number>> }` (`headingRow` is 0-based)
  - `findActivityTable(wb: Workbook): TableMapping | null`: applies the spec's heading rules and synonyms.
  - `interface ImportedActivity { code: string; name: string; phase: string; milestone: boolean; responsibility?: string; criteria?: string; durationDays: number | null; durationFrom: 'file' | 'dates' | null; links: { from: string; type: DepType; lagDays: number }[]; hasPredecessors: boolean; status: string }`
  - `readActivities(wb: Workbook, map: TableMapping, calendar: Calendar): { activities: ImportedActivity[]; warnings: string[] }`. This also covers ID generation (`A001`…), duplicates (`P010-2`), dropping unknown and self links with a warning, the 500 limit (throws), and blank-name rows (skipped).
  - `parsePredecessors(text: string): { from: string; type: DepType; lagDays: number }[]`: handles `P080 FS; P090 SS+5; P100FF-2d`, `Project start`, and comma separators.
  - `mapStatus(raw: string): { status: string; warning?: string }`
  - `interface BasisFacts { projectText: string[]; handoverDate: string | null }`, with `readBasis(wb: Workbook): BasisFacts`
  - `guessProject(projects: readonly Project[], wb: Workbook, basis: BasisFacts): string`: a code, or `''`.

### Task 3: The server's import route

**Files:** Create `server/importPlan.ts` (matching, durations and links), `server/importAi.ts` (two tools: `map_columns` and `estimate_durations`), and `server/importPlan.test.ts`. Modify `server/app.ts` to add the route, the 1 MB body limit for it and the limiter cost, and `src/planner/types.ts` to add the request/response types.

**Interfaces:**
- `ImportRequest`: `{ hints: { fileName: string; sheetNames: string[] }, columns?: { sheet: string; rows: string[][] }[], activities?: { code: string; name: string; phase: string; hasDuration: boolean; hasPredecessors: boolean }[], scheduleType?: string | null }`. Exactly one of `columns` or `activities` is present; validate it and answer 400 otherwise.
- `ImportResponse`:
  - mapping: `{ ok: true; mapping: TableMapping | null }`
  - activities: `{ ok: true; scheduleType: string | null; targetCode: string | null; durations: { code: string; days: number; basis: 'history' | 'template' | 'estimate'; reason: string }[]; templateLinks: { to: string; from: string; type: DepType; lagDays: number }[]; history: HistorySummary | null }`
- `matchScheduleType(catalogs: Record<string, CatalogActivity[]>, acts): string | null`: the type whose codes (or lower-cased names) cover at least 50% of the file activities, else null.
- `templateDurations(...)`: for blank-duration activities in the catalog, use the same statistic `buildHistoryDraft` would (p80 where history has it, else `defaultDays` with basis `template`).
- `templateLinks`: only for matched activities with `hasPredecessors === false`, and only links whose `from` is in the file.
- The AI estimate runs only for blank-duration activities that are not in the catalog. Its output is validated: integer days ≥ 1 (0 for milestones), one per requested code. On failure or bad output, every requested code gets 5 days with basis `estimate` and reason `default: no AI estimate available`.
- Limiter: cost 1 when an AI call will be made (mapping, or at least one estimate), else 0. In-flight slot always.

- [ ] Write tests in `server/importPlan.test.ts`, using a fake history source and a fake Anthropic client as `server/app.test.ts` does:
  - The 44-code property catalog matches `property-development`.
  - With `scheduleType: null` and unknown codes, the result is null.
  - Template durations get basis `template` and reason `from the template, no history yet` when there's no history.
  - An added activity gets an AI estimate; a garbage AI reply falls back to 5 days.
  - Template links only for `hasPredecessors: false`.
  - The cost is 0 when no AI is needed (the hourly count doesn't change).
  - A body over 16 KB is accepted on this route and rejected on `/draft`.
  - The mapping call returns the AI's mapping when valid, and null when the AI says none.

### Task 4: Assemble the draft

**Files:** Create `src/planner/import/importDraft.ts` and its test. Modify `src/planner/types.ts` (`DurationBasis` gains `'file' | 'estimate' | 'template'`; `DraftActivity.status?: string`), `src/planner/sheetFromDraft.ts` (`basisText` handles the new bases and the links note; the activity's `status` is written when set), and `src/planner/plannerApi.ts` (`requestImport(token, body: ImportRequest): Promise<ImportResponse>`).

**Interfaces:**
- `buildImportDraft(input: { activities: ImportedActivity[]; server: <activities response>; scheduleType: string | null; projectName: string; requiredDate: string; fileName: string }): { draft: PlanDraft; warnings: string[]; counts: { fromFile: number; filled: number } }`. It merges the server's durations and template links (flagging `linksFromTemplate` in the reason). The target is the server's `targetCode` if present in the file, else the single activity with no successors, else the last one. `request.scheduleType` is the confirmed id or `'imported'`. `history` is the server's history, or an empty summary.
- `scheduleImport(draft, calendar, today): { plan } | { error: string }`: wraps `planBackward`, turning a cycle or unschedulable plan into an error naming the activities.

### Task 5: The wizard

**Files:** Modify `src/planner/PlannerWizard.tsx`, `src/planner/PlanPreview.tsx` (an `allowRegenerate` prop), `src/planner/plannerWizard.css`, `src/planner/PlannerWizard.test.tsx`, and `e2e/planner.spec.ts`.

**Behaviour:**
- An **Import from Excel** button at the top of the request step opens a hidden `<input type="file" accept=".xlsx,.csv">`.
- **On a file:**
  1. `readWorkbook`.
  2. `findActivityTable`, or the server mapping call if it finds nothing. Still nothing shows `No list of activities found in this file.`
  3. `readActivities`.
  4. The server activities call.
  5. Switch to the step `'imported'`, whose heading is **What we found**.
- **The "What we found" step:**
  - Editable Project type, Schedule type (the listed types plus a `General schedule` option with value `''`), Project (required when listed, defaulting to `guessProject`), and **Planned handover** (required, defaulting to `basis.handoverDate`).
  - A summary line: `<n> activities: <fromFile> durations from your file, <filled> filled in`.
  - A warnings list.
  - Buttons: **Back** (to the form) and **Preview**.
- **Changing the schedule type** re-runs the server activities call, with a loading state on the step.
- **Preview** runs `buildImportDraft` and then `scheduleImport`. An error stays on the step. Otherwise it shows `PlanPreview` with one entry and `allowRegenerate={false}`, and Back returns to `'imported'`.
- **Create** runs `insertSheetFromDrafts([draft])` with the Project column only.
- Errors at any stage show in the existing failure bar, with Retry where it makes sense.
