# Projects for both businesses: Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Make the project required in Plan with AI, list only the chosen project type's projects (with sample property projects), and keep cost codes optional and shown only for Data centre plans.

**Architecture:** One migration renames `procore_projects` to `projects`, adds `project_type` and `in_procore`, and seeds four sample property projects. The client types, loader and helpers are renamed to match. The wizard filters the list by project type, requires a project when the list has any, and gates Cost code and Delivery site on Data centre.

**Tech Stack:** TypeScript, React 18, Vitest + Testing Library, PGlite migration tests, Supabase, Playwright e2e.

**Spec:** `docs/superpowers/specs/2026-11-22-projects-design.md`

## Global Constraints

- **Table:** `projects(code, name, is_program, in_planner, project_type text not null default 'data-centre' references project_types (id), in_procore boolean not null default true)`. Existing rows keep the defaults.
- **Sample projects:** all with `project_type 'properties'`, `in_procore false`, `is_program false`, `in_planner true`:
  - `VIL-01` Sample villa
  - `TWR-01` Sample tower
  - `MC-01` Sample master community
  - `INF-01` Sample infrastructure
- **Wizard field:** labelled **Project**. It lists only projects whose `projectType` equals the chosen project type, program projects first, then by code (the server's order). When the options have no project types at all, every project is listed.
- **Required:** when at least one project is listed, Generate is blocked with the exact message `Choose the project`. With none listed (empty or failed to load), the field is hidden and not required.
- **Changing project type** clears a chosen project that isn't listed under the new type.
- **Cost code and Delivery site** show only when the project type is `data-centre` (or when the options have no project types). Delivery sites are the listed projects that are not programs.
- **Sheet column:** titled **`Project`** (was `Procore project`). Same position, values and rows as before.
- **Sync flag:** nothing reads `in_procore` yet. It's carried to the client as `inProcore` for the coming sync.

## Review Focus

1. **Properties chosen:** only sample projects show, there are no cost code or site fields, Generate needs a project, and the sheet has a Project column but no Cost code or Delivery site column. Pinned in Task 4.
2. **Switching Data centre → Properties after picking `BKK-03`:** the project clears, and items' delivery sites clear with it (they followed the project). Pinned in Task 4.
3. **The project list fails to load:** planning still works and nothing is required. Pinned in Task 2 (loader) and Task 4 (wizard).
4. **Existing sheets** with a `Procore project` column are untouched (no data migration of sheets). This is checked by reading the migration: it only touches the `projects` table.
5. **Live database:** migration `0022` renames a table the live app reads. Deploy and migrate together, since old code reading `procore_projects` would lose the list (planning still works). Noted in the PR's deploy line.

### Task 4: Wizard behaviour

**Files:**
- Modify: `src/planner/PlannerWizard.tsx`
- Test: `src/planner/PlannerWizard.test.tsx`, `e2e/planner.spec.ts`

**Interfaces:**
- Consumes: `projectsFor`, `DATA_CENTRE` and `siteProjects` (Task 2), and `insertSheetFromDrafts` (unchanged).
- Behaviour:
  - **Listed projects:** `listed = projectsFor(options?.projects ?? [], options?.projectTypes?.length ? projectType : '')`, memoised.
  - **Data centre check:** `dataCentre = !options?.projectTypes?.length || projectType === DATA_CENTRE`.
  - **Gating:** `costCodes` and `sites` are empty unless `dataCentre`. Sites are built from `listed`.
  - **The field:** labelled **Project**, rendering `listed`. Rename the `procoreProject` state and ids to `project` / `ids.chosenProject`. `ids.project` stays the project *type*.
  - **Required:** `projectProblem = listed.length > 0 && !project ? 'Choose the project' : null`, and `problem = projectProblem ?? firstProblem(form, errors)`. When submitted with a project problem, the select gets `aria-invalid` and the `FieldError` reads the same text.
  - **Clearing on type change:** an effect on `[listed]` sets `project` to `''` when it isn't among `listed`.
  - **Create:** passes `project` options from `listed`. Cost codes and sites are only passed when they're non-empty, as today.
